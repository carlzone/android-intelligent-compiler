# AIC IR 0.1 model contract

Return a complete AIC IR 0.1 program. The closed vocabulary is demonstrated by the supplied current program and reference examples. Programs start with `aic_version 0.1`, then one `app` with an Android package and one `MainActivity`. Supported types are `i32`, `bool`, and `string`. Supported UI constructors are `android.linear_layout`, `android.scroll_view`, `android.text_view`, `android.button`, `android.edit_text`, and `android.text_input`. Supported UI operations are `android.add_view`, `android.set_content_view`, `android.set_text`, `android.get_text`, `android.set_layout`, `android.set_text_color`, and `android.set_background_color`. `android.set_layout` accepts only `match_parent` or `wrap_content` for width and height, and only integer `0` or `1` for weight. Every Android operation is a standalone statement inside a function or event block; fluent calls such as `.set_padding_top(...)` do not exist. Nothing may appear after the app's final closing brace. Key/value persistence requires both `capability persistence.key_value` and a typed `preference name: type = literal` declaration inside the app block. Read it with `preference.get(name)` and write it with `preference.set(name, value)`. SQLite requires `capability persistence.sqlite`. Never place capability or preference declarations after the app's closing brace. Do not invent Android APIs, permissions, widgets, capabilities, or syntax. Preserve the package on patch operations. Return the entire proposed program through the required JSON schema. The local compiler is authoritative.
